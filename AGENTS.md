# AGENTS.md

Repository-specific knowledge for AI agents working in this codebase.

## What this project is

An Android app (Capacitor + React) that captures the screen, runs on-device
computer-vision analysis, detects coloured objects, and tracks cups for
Thimbles-style games. Analytics and session history persist locally.

The core intent is on-device capture and analysis. There is no server
component, and the APK reads no `.env` file.

## Build and verify

```bash
npm install
npm run build        # web bundle -> dist/
npm run apk          # dist/ + cap sync + gradle assembleDebug
npm run preview      # serve dist/ on port 4173
npm run test:vision  # JS vision vs Python reference
```

The debug APK lands at `android/app/build/outputs/apk/debug/app-debug.apk`.

Vision parity needs a fixture generated by Python before it can run:

```bash
pip install opencv-python numpy
python3 scripts/reference_tracker.py .parity
npm run test:vision
```

`.parity/` is generated and gitignored. If `test:vision` reports a missing
fixture, run the generator — that is expected, not a broken test.

Android lint: `cd android && ./gradlew :app:lintDebug`. The project builds
clean of lint errors; remaining warnings are icon/dependency noise.

## Layout

- `src/services/` — the whole pipeline. `capture/` picks a frame source,
  `vision/` detects, `tracking.js` tracks cups, `analytics.js` summarises,
  `storage.js` persists.
- `src/services/vision/config.js` — single source of truth for vision tuning.
  The Python oracle and `.env.example` are kept in sync with it.
- `android/app/src/main/java/com/favie/xtracker/` — `ScreenCapturePlugin.java`
  (MediaProjection) and `ScreenCaptureService.java` (foreground service).
- `app/tracking.py` — OpenCV reference implementation. It is the parity oracle,
  not app code. Do not delete it.

## Things that will bite you

- Android 14+ throws if `getMediaProjection` is called without a foreground
  service of type `mediaProjection`. The service must start first. See
  `ScreenCaptureService.java`.
- `<uses-permission>` elements must precede `<application>` in the manifest.
  Android lint flags `ManifestOrder` as a correctness issue otherwise.
- Capacitor 7 requires JDK 21. The CI workflow pins it for that reason.
- `capacitor.config.json` is JSON on purpose: a `.ts` config would require
  installing TypeScript just to run the CLI.
- Capacitor plugin registration is explicit in `MainActivity.java`. Adding a
  plugin class without registering it fails silently at runtime.

## Historical context

Deleted files that are deliberately not restored (see commit "Restore the
documented userscript and correct the docs"):

`electron/preload.js`, `public/App.js`, `public/index.html`, `src/index.js`,
the old `.js` components, `logic.js`, `simulator.js`, `tracking.js`. All were
fragments of an Electron + Flask desktop design whose backend was never
committed. `window.api` in the old components points at a Flask server on
localhost:5000 that does not exist here.

`INSTALL.md` and `README-APP.md` still describe that old design and carry a
note saying so. The root `README.md` is authoritative.

## Deployment

No device-emulator verification is possible in CI containers without KVM.
Validation is static: `apksigner verify`, `apkanalyzer manifest print`, and
checking for the capture classes in the dex.
